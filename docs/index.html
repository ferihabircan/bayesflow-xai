Install

  1. Create and activate a virtual environment

    $ python -m venv .venv
$ source .venv/bin/activate

  2. Install the package (editable) and its dependencies

    $ pip install -e .
# or: pip install -r requirements.txt

  3. Set your GPU / backend (copy the example env file)

    $ cp .env.example .env
# .env sets KERAS_BACKEND=torch and CUDA_VISIBLE_DEVICES=<your GPU index>
# note: src/bayesflow_xai/utils/config.py sets a default at import time --
# check that default matches an idle GPU on a shared machine before running.

Usage

# the general, config-driven entry point -- any registered
# simulator x summary network x XAI method:
$ python scripts/run_workflow.py --config configs/workflow_example.yaml

# original per-pipeline scripts still work exactly as before:
$ python scripts/run_diagnostics.py
$ python scripts/run_xai.py --target lambd --stats
$ python scripts/run_lv_xai.py --target theta0 --stats
$ python scripts/run_grf_xai.py --target alpha
# registering your own simulator (see bayesflow_xai/registry.py for the full docstring)
from bayesflow_xai.registry import register_simulator, SimulatorSpec

@register_simulator("my_sim", targets=["theta"])
def build_my_sim_spec() -> SimulatorSpec:
    from my_lab.my_dataset import build_my_tensor_dataset
    return SimulatorSpec(
        name="my_sim",
        param_names=["theta"],
        input_kind="timeseries",          # or "image"
        build_tensor_dataset=build_my_tensor_dataset,
        channel_names=["x"],
        in_channels=1,
    )

# then: simulator: my_sim   in your own workflow .yaml

inference_network: coupling_flow
target: lambd                # must be a registered target for the simulator

# integrated_gradients | saliency_map | attention_rollout | masking

Models

simulator/sir

SIR

lambd · mu · D · I0 · psi

Stationary Susceptible-Infected-Recovered epidemic model from the BayesFlow tutorial: a prior over infection/recovery dynamics, forward-simulated case counts observed through negative-binomial noise.

simulator/lotka_volterra

Lotka-Volterra

theta0 · theta1 · theta2

Despite the name, a theta-parametrized sinusoidal signal with additive Gaussian noise (kept verbatim from the source example) -- a 2-channel timeseries testbed for the same XAI surrogate pipeline as SIR.

simulator/grf

Gaussian Random Field

log_std · alpha

BayesFlow's spatial-data example: a 64×64 field generated from a power-law spectrum. Two scenarios -- (log_std, alpha) as inference target, and the field itself generated via a conditional diffusion model.

XAI Methods

gradient path

Integrated Gradients

Walks a straight-line path from a zero baseline to the real input, accumulating the output's gradient at every step, to attribute the prediction to each input value.

raw gradient

Saliency Map

The simplest XAI method: the raw gradient of the output with respect to the input, no baseline or path integral -- cheap, but noisier than Integrated Gradients.

transformer

Attention Rollout

Multiplies a transformer's per-layer attention weights (mixed with a residual/identity term per layer) to trace how information from each time step flows to the output through every layer.

new · black-box

Masking / Occlusion

No gradients at all: cover part of the input (a time step, or an image patch) with a zero baseline and measure how much the prediction moves. Works even against models Captum can't differentiate through.

Results

GRU summary networks over-weight sequence endpoints

Every GRU surrogate here reads out only the final hidden state, so the last time step reaches the output through a single update while earlier steps are diluted through many compounded ones -- endpoints dominate |IG attribution| almost by construction. Channel/time importance stats exclude both endpoints from the reported "important time steps" for this reason (see methods/integrated_gradients.py).

Attention rollout and Integrated Gradients agree on SIR

The transformer's rolled-out attention concentrates on the outbreak's rising/peak region, the same window Integrated Gradients ranks highest for the Infected (I) channel -- two independent methods converging on the same explanation is a useful sanity check for either one alone.

Masking is gradient-free but far more expensive

Occlusion needs one forward pass per masked time step/patch instead of one backward pass total, so it scales with input size -- worth it specifically because it needs no autograd support from the model, unlike the other three methods here.

Add your own simulator or XAI method

Everything selectable from a config lives in one registry (src/bayesflow_xai/registry.py) populated by src/bayesflow_xai/registrations.py. Registering something new is a decorator, in your own module:

# my_lab/my_xai_method.py
from bayesflow_xai.registry import register_xai_method

@register_xai_method("my_method")
def my_method(spec, body, head, X_val, y_val, target_idx, target_name, fig_prefix, **kwargs):
    # spec: SimulatorSpec (input_kind, channel_names / field_shape, ...)
    # body/head: trained surrogate -- head(body(x)) -> target predictions
    # return whatever you plot; bayesflow_xai.utils.plotting.show_and_save()
    # saves figures the same way every other method does.
    ...

Import your module once (e.g. at the top of your own copy of scripts/run_workflow.py, or add it to registrations.py) so the decorator runs before the config lookup -- then reference it by name from any workflow .yaml.
