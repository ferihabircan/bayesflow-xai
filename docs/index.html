What do neural summary networks look at? Explaining amortized Bayesian inference with attribution methods

Feriha Bircan
Research internship project · 2026
Code Write-up (PDF) Key finding

Abstract

Amortized Bayesian inference with BayesFlow compresses raw simulator output into a learned summary vector before a normalizing flow turns it into a posterior. Whether that summary is built from the physically meaningful part of the data is usually checked only indirectly, through parameter recovery and calibration. This project applies four post-hoc explanation methods — Integrated Gradients, Saliency Maps, Attention Rollout and Masking/Occlusion — to summary networks trained on four simulators of increasing complexity: a stationary SIR epidemic model, a Lotka-Volterra-style sinusoidal signal, a Gaussian Random Field, and a gravitational-wave benchmark. All combinations are run through one config-driven plugin registry.

On the toy signal, attributions recover the known ground truth (the channel that a parameter scales is the dominant channel in 188 of 200 samples). On the gravitational-wave benchmark, Integrated Gradients shows that a network trained on min-max-scaled inputs ignores the merger and relies on a non-physical ~20 Hz whitening artefact of the original simulator; z-score inputs move the attribution onto the merger and cut validation error from 9.27 to 1.41. Integrated Gradients and Masking agree closely (rank correlation 0.99), while plain Saliency puts most of its mass in signal-free regions. The SIR experiments show the limits: methods disagree on which population channel matters, and recurrent read-outs bias attributions toward sequence endpoints.

01

Motivation

In simulation-based inference (SBI) the likelihood is only available as a simulator. BayesFlow trains a summary network that maps a data set x to a fixed-size vector and an inference network (a conditional normalizing flow) that maps that vector to the posterior p(θ | x). After training, inference for a new data set is a single forward pass: the cost of inference is amortized over many data sets.

The standard checks — loss curves, parameter recovery, simulation-based calibration (SBC) — say whether the posterior is accurate on simulated data. They do not say why. A network can reach a good loss by exploiting a simulator artefact that will not exist in real observations. Explainability methods give a direct, per-input view of what the summary network relies on, which is what this project tests:

  • Do attributions recover what we know is informative when the ground truth is known?
  • Do different XAI methods agree with each other on the same trained model?
  • Can attributions reveal problems that the usual SBI diagnostics miss?
02

Method

Each simulator is used twice: to train a full BayesFlow posterior (checked with the standard diagnostics), and to train a plain-PyTorch surrogate regressor of the same summary-network family, on which the attribution methods are computed.

Why a surrogate?

Captum's attribution methods need a plain torch.nn.Module with a scalar output. The surrogate is a summary network of the same architecture plus a linear head that predicts one parameter, so the attributions describe what that architecture learns to extract from the data. They do not explain the full normalizing-flow posterior; the latent-space projection is the one analysis run on the BayesFlow summary network itself.

03

Results

All numbers below are read from the figures and logs in the repository; nothing here was re-tuned for this page.

The posteriors are accurate where the data are informative

For SIR (6000 simulations, 100 epochs), recovery is close to perfect for the infection rate λ (r = 0.98), good for ψ (0.86) and I₀ (0.74), and weak for the recovery rate μ (0.18) and the reporting delay D (0.41): with a 60-day window of noisy case counts these two are only weakly identified, and their posteriors correctly stay wide. The SBC rank histograms stay inside the grey confidence band, consistent with a calibrated posterior. For the GRF, both parameters are recovered almost exactly (r = 0.999 and 0.993) and the ECDF calibration curves stay inside the 95% band.

Sanity check: attributions recover the known ground truth

In this toy signal θ₀ is, by construction, the amplitude of channel X1 only. A GRU surrogate (R² = 0.98 for θ₀ on held-out data) explained with Integrated Gradients puts the largest total attribution on X1 in 188 of 200 validation samples. The most important interior time steps cluster at steps 3–6 and 13–17, around the extrema of the sine where the amplitude is easiest to read.

SIR: the methods do not agree on which channel matters

The SIR surrogate (GRU on the full S, I, R trajectories) only learns λ well (held-out R² = 0.90; R² ≤ 0.03 for μ, D, I₀, ψ), so all SIR explanations target λ.

Two effects make these rankings hard to read.

(1) Endpoint effect: the GRU surrogates read out only the last hidden state, so the final time step reaches the output through one update and dominates |attribution| almost by construction; this is why the statistics exclude both endpoints, and why Masking peaks at the last step. (2) Baseline effect: IG multiplies the gradient by (x − baseline). With a zero baseline, S (≈ 1 for most of the window) gets a large factor while I (a few percent) gets a small one. Saliency, which has no such factor, ranks R first. The S-dominance under IG is therefore at least partly a property of the baseline, not only of the model.

GRF: attribution is spread over the field, low at the border

α controls the spatial correlation of the whole field, so no single region should carry it, and the mean attribution maps are indeed diffuse. Both gradient methods show a dark frame of about 3–5 pixels, which is consistent with the zero padding of the 3×3 convolutions (border pixels feed fewer receptive fields). Masking 8×8 patches gives a coarser map with the same low-importance border column on the left and right. These maps describe a CNN surrogate trained for 30 epochs on 2000 fields.

Where the artefact comes from

PyCBC starts the waveform below 20 Hz, but the noise PSD has no power there, so whiten() (which estimates the PSD from the data) amplifies the sub-20 Hz inspiral by about four orders of magnitude; the 20 Hz FIR high-pass removes only ~6× of it. Every sample is dominated by a ~20 Hz bell from −1.5 s to +0.5 s that continues past the merger, and min-max scaling spends almost the whole [0, 1] range on it. The simulator is deliberately left unmodified: the artefact is a result of the analysis.

The two z-score trainings reached val. MSE 1.41 and 0.60, so single-run numbers should be read with that spread in mind.

04

Discussion

Attributions can find bugs that diagnostics miss

The min-max GW model has a working loss curve; only IG showed it was reading the whitening artefact instead of the merger.

Agreement is the useful signal

IG and Masking agree on the GW model (ρ = 0.99) although one uses gradients and the other only forward passes. Where methods disagree (SIR channels), no single map should be trusted.

Architecture and baseline shape the maps

Last-state GRU read-outs inflate endpoints, zero baselines favour large-magnitude channels, CNN padding darkens borders, dilations leave a grid in Saliency.

05

Limitations

  • Surrogates, not the posterior. Attributions are computed on MSE regressors of the same architecture, not on the BayesFlow summary network + flow. For SIR the surrogate also sees S/I/R instead of the case counts.
  • Only some parameters are explained. The SIR surrogate learns only λ (R² 0.90); its targets are not standardised, so the MSE is dominated by the high-variance, weakly identified I₀ and ψ.
  • Single runs. Most figures come from one training seed. The two GW z-score runs differ in val. MSE by more than 2×.
  • No quantitative faithfulness test. Methods are compared with each other and with known structure, not with deletion/insertion curves or randomisation checks.
  • Baseline choice. IG used a zero baseline for SIR, Lotka-Volterra and GRF; other baselines were not compared systematically.

Reproduce

Python ≥ 3.10. Set CUDA_VISIBLE_DEVICES for your machine first (the code defaults to GPU 8 of the lab server).

git clone https://github.com/ferihabircan/bayesflow-xai.git
cd bayesflow-xai
python -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"          # add ,gw for the gravitational-wave simulator (PyCBC)
export CUDA_VISIBLE_DEVICES=0    # or "" for CPU
pytest
# any simulator x summary network x XAI method, from a YAML file
python scripts/run_workflow.py --config configs/workflow_example.yaml
python scripts/run_workflow.py --config configs/workflow_example.yaml --n_sims 200 --epochs 2   # smoke run

# BayesFlow posterior + diagnostics (SIR)
python scripts/run_diagnostics.py

# original per-simulator pipelines
python scripts/run_xai.py --target lambd --stats
python scripts/run_lv_xai.py --target theta0 --stats
python scripts/run_grf_xai.py --target alpha

# gravitational wave
python scripts/run_workflow.py --config configs/gravitational_wave_zscore_workflow.yaml
